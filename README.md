# TimeTracker Practice

Учебный проект по дисциплине «Программирование корпоративных систем».

## Суть проекта

TimeTracker — это консольный тайм-трекер для учета рабочего времени по задачам.
Текущая версия умеет создавать задачи, запускать и останавливать таймер,
добавлять записи вручную, показывать журнал, формировать отчеты по задачам
и по дням, а также сохранять данные в CSV-файлы.

## Структура

- `include/` — публичные заголовочные файлы проекта.
- `src/` — исходные файлы реализации.
- `tests/` — unit-тесты Catch2 и сценарные мини-программы.
- `external/catch2/` — локально подключенная заголовочная версия Catch2.
- `CMakeLists.txt` — настройка сборки через CMake.

## Сборка

```bash
cmake -S . -B build
cmake --build build
```

## Запуск

Для Windows после сборки Visual Studio:

```bash
.\build\Debug\timetracker.exe --demo
.\build\Debug\timetracker.exe
.\build\tests\timetracker_tests.exe
```

Для Linux или macOS:

```bash
./build/timetracker --demo
./build/timetracker
./build/tests/timetracker_tests
```

## Тестирование

Проект использует Catch2 для unit-тестов. Тестовые исполняемые файлы собираются
в отдельную директорию `build/tests`.

Запуск всех тестов и сценариев через CTest:

```bash
ctest --test-dir build -C Debug --output-on-failure
```

На Linux или macOS, где CMake обычно использует single-config генератор, параметр
`-C Debug` можно не указывать:

```bash
ctest --test-dir build --output-on-failure
```

Состав тестовой части:

- `timetracker_tests` — unit-тесты классов `Task`, `TimeEntry`,
  `TimeTrackerService`, `ReportService`, `Storage`, `DateTimeUtils`,
  `ConsoleApp`;
- `scenario_basic_workflow` — сценарий создания задачи, запуска и остановки
  таймера;
- `scenario_persistence` — сценарий сохранения и загрузки CSV-файлов;
- `scenario_console_workflow` — сценарий работы через консольное меню.

## Главное меню

После запуска без параметров программа показывает меню:

1. создать задачу;
2. вывести список задач;
3. запустить таймер;
4. остановить таймер;
5. добавить запись вручную;
6. показать журнал;
7. сформировать отчет по задачам;
8. сформировать отчет по дням;
9. сохранить данные;
0. выйти.

Ручная запись времени вводится в формате `YYYY-MM-DD HH:MM`.
Например: `2026-05-31 14:30`.

## Сторонние библиотеки

Сторонние библиотеки не используются. Проект написан на C++17 и использует
только стандартную библиотеку C++.
